# ورود تست‌های زده‌شده قبلی — توضیح دقیق برای عامل

## جریان UX اجباری (درخواست کاربر)
1. کاربر فقط **کتاب** را انتخاب می‌کند.
2. سیستم یک **لیست بزرگ** از سوال‌های آن کتاب نشان می‌دهد (گروه‌بندی بصری بر اساس فصل → مبحث).
3. برای هر سوال دقیقاً یکی:
   - گزینه ۱
   - گزینه ۲
   - گزینه ۳
   - گزینه ۴
   - **نزده** (صریحاً جدا — نه خالی مبهم)
4. دکمه ثبت نهایی → برای هر ردیف که کاربر دست زده attempt ساخته شود.

## جزئیات پیاده‌سازی
- پیش‌فرض همه ردیف‌ها «نامشخص»؛ فقط ردیف‌های علامت‌خورده ذخیره شوند یا کل لیست با حالت نزده صریح.
- بهتر: سه حالت UI: بدون‌تغییر | پاسخ ۱..۴ | نزده
- بعد از ثبت:
  - session با `is_imported=true`
  - result از مقایسه با answer_key (اگر answer_key نبود → pending_correction)
  - wrong و unanswered → review_queue
  - بدون سکه

## فیلتر کمکی (اجباری برای لیست خیلی بزرگ)
- فیلتر فصل / مبحث (اختیاری روی همان صفحه) تا لیست کوتاه شود — ولی مسیر اصلی همچنان «از کتاب» است.

## API
`POST /attempts/import-by-book`
```json
{
  "book_id": 1,
  "items": [
    {"question_id": 10, "choice": 2},
    {"question_id": 11, "choice": null, "unanswered": true}
  ]
}
```
`choice` و `unanswered` همزمان true ممنوع.

## اشتباهات ممنوع
- قاطی کردن unanswered با wrong
- اجبار به انتخاب مبحث قبل از دیدن لیست (خلاف خواست کاربر)
- ذخیره بدون امکان نزده
