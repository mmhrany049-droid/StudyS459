# بانک تست و پاسخ‌نامه — توضیح دقیق برای عامل کدنویس

## مشکل نسخه‌های قبلی
ورود تست/پاسخ‌نامه بد ساخته شده بود: نامشخص، پراکنده، یا بدون مسیر واضح UI.

## مسیر UI اجباری
```
کتاب‌ها
 └── [نام کتاب]
      └── درخت مباحث
           └── هر مبحث (برگ یا عنوان)
                └── دکمه/تب «بانک تست این مبحث»
```

یک **بخش جدا در هر کتاب** برای مدیریت بانک تست وجود داشته باشد (نه مخفی داخل تنظیمات).

## مدل ذهنی
- هر مبحث → صفر یا یک Test Set پیش‌فرض از نوع `normal` (یا چند set اگر level دارد)
- حسابان: برای هر بخش می‌تواند سه set با difficulty 1/2/3 باشد
- هر سوال: `sequence_no` (۱..N)، `answer_key` در {1,2,3,4} یا خالی تا وقتی کاربر پر کند

## صفحه بانک تست مبحث — اجزای اجباری
1. عنوان مبحث + تعداد سوال تعریف‌شده + تعداد دارای جواب
2. دکمه «افزودن بازه»: از N تا M → سوال با sequence می‌سازد (جواب خالی)
3. **لیست بزرگ پاسخ‌نامه چهارگزینه‌ای**:
   - ردیف: شماره سوال | دکمه ۱ | ۲ | ۳ | ۴ | پاک‌کردن جواب
   - اسکرول روان برای صدها ردیف
4. ذخیره دسته‌ای (یک API bulk)
5. اختیاری: سختی برای حسابان

## ورود سریع (الزامی طبق پیشنهاد S1/S2)
- کلید ۱..۴ همان ردیف فوکوس؛ ۰ یا Space = بدون جواب؛ Enter = بعدی
- جعبه «چسباندن پاسخ‌نامه فشرده»:
  - قالب A: `1:2,2:3,3:1`
  - قالب B: `23140...` (رقم‌به‌رقم؛ ۰=بدون جواب)

## API حداقلی
- `GET /books/{book_id}/nodes/{node_id}/questions`
- `POST /books/{book_id}/nodes/{node_id}/questions/range` body: `{from,to}`
- `PUT /books/{book_id}/nodes/{node_id}/answer-key` body: `{items:[{sequence_no, answer_key|null}]}`

## قوانین
- sequence یکتا در test_set
- حذف سخت اگر attempt دارد ممنوع → soft disable
- موتور تست فقط از سوال‌های همین node/set انتخاب کند
